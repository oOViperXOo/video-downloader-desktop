# Download features

- **Performance:** options dialogs are created when opened; unchanged queue rows survive refreshes. Progress data is recorded immediately while row paints are coalesced at 100 ms intervals. Terminal states still update immediately. The current widget-based table remains in place.
- **Release formats:** one Setup EXE defaults to a single Portable EXE, with optional installation of a faster folder bundle. Both use existing AppData settings/history. Portable unpacks runtime tools temporarily on launch and adds no shortcuts or uninstall registration. Installed mode adds a Start menu shortcut and Windows uninstall entry. Existing portable-folder data is preserved; select a separate folder for the new format.

- **Single instance:** repeat launches restore the existing window, including from the system tray. The per-user lock is released at exit and stale process locks recover after a crash. Engine/download worker subprocesses remain independent of the GUI lock.

- **Compact download table:** each file occupies one 44-pixel row with grid lines. Columns are File, Status/progress, Speed/ETA, Quality and Actions. The overflow button opens a compact dialog with Media, Save as and Connections; exact formats, Start all inclusion and optional MP4 copies sit under More options. Light and dark themes explicitly style combo boxes and their popup palettes.
- **Unified page:** the link field, Add, Start/Pause all and one three-dot menu share the top row. Settings and output-folder actions are in that menu. Active items and saved completed records share the table, without duplicate current completion records. Archived records have Open and single-record removal actions. No navigation header or bottom footer takes table space.
- **Table widths and actions:** drag the File header divider to resize filenames. Actions stays narrow. Clear completed and cancelled items removes their list/history records while preserving downloaded files.
- **Window sizing:** the app starts at 960 × 520, can shrink to 760 × 360, and fits table columns to the viewport as the window changes size. Filename columns remain manually resizable; relative column preferences are retained while resizing the window.
- **Playlist organization:** Settings > Advanced naming offers a separate playlist folder, a folder name using `{playlist}` or custom text, and optional order prefixes (`001 -`, `002 -`, etc.). The filename template still controls titles/extensions and retains the full video ID. Invalid Windows folder characters are replaced, and playlist names cannot escape the download directory. Choices apply to newly added playlists; single videos keep the normal folder. The playlist directory is created when downloading begins.
- **Account sign-in:** Settings > Login and network lets you choose the download browser and website, then open that browser to sign in. Apply afterward to use its session for new inspections/downloads. The app does not collect passwords or claim to be signed in before a request succeeds. Stop using browser login selects `none`; Apply to stop new requests using the browser session. This does not sign you out of the website. Browser cookie access and individual site support can still limit authenticated downloads.

- **Minimize to tray:** enabled by default under Settings > General. Minimize the main window to keep downloads/schedules running in the background. Click the tray icon to restore it, or right-click for Show window, Open download folder, Pause all downloads and Quit. Quit retains the existing active-download confirmation. The window Close button still exits. If no system tray is available, normal taskbar minimization is retained.

- **Quick add and formats:** copied links appear in the inline link field. Click Add to inspect and queue them, choose quality, format and connection mode directly on each ready item, then use Start or Start all. Format popups scroll and show estimated sizes where available. Playlist entries without format metadata use quality defaults; only the first entry is probed automatically. Watch Later and Liked Videos require your logged-in browser under Settings > Login and network.
- **Batch input:** use Queue actions > Add several links, paste multiple lines with the Add link Paste button, or drop links on the window. URL aliases and duplicates already in the queue are skipped. Each link is inspected in sequence; cancelling or failing an inspection stops the remaining batch.
- **Retries:** Settings > Schedule and updates allows 0–3 automatic retries. Transient network errors use bounded backoff; login, DRM, unsupported links, permission/disk failures and user-paused/cancelled items do not auto-retry.
- **Ordering:** select queue entries and use Queue actions to move up/down or prioritize. Existing workers keep running; priority determines the next available slots.
- **Disk space:** before starting, available space is checked with estimated temporary-file/conversion headroom and reservations for active jobs. Unknown sizes cannot guarantee the file will fit. Low-space items pause with an explanation.
- **Completion:** the latest completion has Open file/Open folder actions in the app and a system tray notification when Windows supports it. A completed MP4-copy notification opens the copy; the original path remains preserved in the job.
- **Scheduling:** set a local start date/time and optional quiet hours in Settings > Schedule and updates. The app must remain open. Quiet hours hold new starts while active transfers finish.
- **Search/filter:** history can filter by title/URL/path text, site, status and date prefix. Filtering does not remove stored records. Single-record history removal and separate confirmed Clear all remain available. Downloads uses the inline link field instead of a filter row.
- **MP4 copies:** opt in while choosing formats, or right-click one completed non-MP4 video (including history) and use make MP4 copy. Small/Balanced/High presets create a separate H.264/AAC file by re-encoding. Size estimates are rough and depend on content/resolution. Original downloads remain untouched; output uses a unique filename. Interrupted conversion restarts rather than resuming encoding. Force-killing a worker can leave a hidden `.conversion-*.mp4` temporary file; no incomplete visible final copy is published.
- **Signing and updates:** the optional signing pipeline and read-only HTTPS update checker are prepared. This build remains unsigned because no trusted signing provider/certificate is configured. Update hosting is not configured; see RELEASE-SETUP.md before publishing a manifest. Checking for updates never installs or executes a downloaded binary automatically.

Torrent support remains cancelled and was not implemented.

- **Row actions:** Open, Show in folder, Copy link, Open download page, Rename, Move, Delete file (confirmation), Change URL, Make MP3 copy, conditional make MP4 copy, and Remove from list. Bulk copy-link, move, delete and list removal support multiple selection. Rename/move update matching queue and history paths. File moves run in the background and protect existing destination files. Change URL starts a fresh destination and retains old partials. Double-click opens completed files after checking existence.

- **Automatic playlist filename prefix:** configure once in Settings > Playlists. Enable the automatic prefix and choose 01/001 with a live example. New playlists inherit the setting at Add time; their source indices are preserved. Existing queue items and single videos keep their filename templates. There is no per-playlist Apply dialog, toolbar button or row-menu numbering action.
